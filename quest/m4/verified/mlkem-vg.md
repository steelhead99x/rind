# [M] ML-KEM-768 earns the ✓ from pyca/verified-garbage's proof

## Goal

ML-KEM-768 earns the ✓ on the tiers that run pyca/verified-garbage's (VG) routines: its encapsulation key check and encapsulation on every x86_64 CPU and on aarch64 with the SHA-3 instructions, and its key generation and decapsulation on x86_64 with AVX-512 (`low/<arch>/mlkem768_vg.rs`, vendored by `admin/import-vg`).

## Plan

- Done: `proofs/Rind/<Arch>/VgMlKem.lean` restates VG's contract for each routine as one axiom about rind's opaque wrapper in `low::<arch>::mlkem768_vg`, over VG's FIPS 203 spec (`Spec/MlKem.lean`, vendored by `admin/import-vg-models`). Each wrapper picks among VG's variants, which all state the one contract, through raw pointers Aeneas cannot translate, so the axiom is per wrapper and its docstring names every routine and links every theorem it restates (✅ per wrapper, rejected: a hand model of the x86_64 `encaps` dispatch with one axiom per routine; maintainer, 2026-11-17). ML-KEM-768 samples four at a time on rind's fallback, so Graviola's unproven AVX-512 eight-way sampler is off its path.
- Left: prove rind's glue as the m4 epic proves rind's other glue. `mid/mlkem.rs` picks VG's routine per key, encodes a VG key as FIPS 203's `dk` for decapsulation, and falls back to rind's arithmetic when a routine reports that a `SampleNTT` reached VG's bound. Compose VG's `Outcome` with the construction's theorems into SymCrypt's `KeyGen_internal`, `Encaps_internal`, and `Decaps_internal`, bridging VG's `Spec/MlKem.lean` to SymCrypt's spec. Then add the `benchmarks/verified.toml` entries for the switched tiers and pin the axioms in each target's `Axioms.lean`.
