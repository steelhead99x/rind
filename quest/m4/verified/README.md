# Every rind path is proven, with the smallest trust base

## Goal

Every operation rind exports earns `benchmarks/verified.toml`'s strict ✓ on every hot tier of x86_64 and aarch64 (the cold tiers are [m5's](/quest/m5/verified/README.md)), including what m3's audit accepted as a gap, and every algorithm m4 adds. What those proofs trust shrinks to the published theorems, Lean, and Aeneas.

### Rules

Moved here when the m3 verification epic was retired (maintainer, 2026-11-17, from [kixel-ai/rind#865](https://github.com/kixel-ai/rind/pull/865); rejected: `proofs/README.md`, leaving the move for later). Its goal, every operation verified on every path, is this epic's, and its audit (2026-11-03, listing what each path ran, what was proven, and the cheapest route to a proof for each gap) is superseded by the audit above and [the recurring re-audit](/quest/m4/verified/re-audit.md); git history keeps its list.

Decided with the maintainer on 2026-11-03: every operation rind exports, on every path, runs code whose whole computation is covered by a published formal proof, so the benchmark report's strict ✓ appears on every rind cell. A ✓ needs the whole computation proven, padding and protocol glue included (after `BENCHMARKS.md` adopted its strict rule). A gap that can't be closed is recorded with its reason.

#### Composition rule

A proof of rind's Rust relies on an imported routine's published theorem only through one axiom per routine, in `proofs/Rind/<Arch>/`.

- The axiom is about the opaque Rust wrapper around that routine, and states the theorem's postcondition over the wrapper's arguments and result as the Lean model reads them (`wordsNat` for HOL Light's `bignum_from_memory`), and nothing more. Its docstring names the theorem and links it at the pinned revision.
- Each precondition of the theorem holds for every call safe Rust can make (no aliasing, the ABI's stack alignment), or becomes a hypothesis of the axiom.
- A function the theorem's statement names, such as `rfcx25519`, is an `opaque` Lean constant whose docstring cites its definition; no proof assumes more about it. A function a proof must compute, such as `group_pow p256_group` for the generator table, is instead its HOL Light definition, transliterated, through the pinned theorems that make it concrete (`P256_GROUP`'s `group_mul`), each linked in its docstring, and every law about it, such as associativity, is proven in Lean, never assumed (2026-11-05, from [kixel-ai/rind#343](https://github.com/kixel-ai/rind/pull/343): transliterate the definitions ✅ / restate HOL Light's group-law theorems as axioms / keep the table's hypothesis).
- A group-membership fact a proof must decide, such as a point being in `group_carrier p256_group`, may be stated as its defining equation, citing the pinned HOL Light theorem it follows from (`P256_GROUP`) (2026-11-04: amend the rule ✅ / a separate axiom / drop the ✓).
- Every other untranslated item is `opaque`, not an axiom. A fact a proof needs about one, such as rind's CPU checks passing, is a hypothesis of the theorem.
- Rust on the path that Aeneas cannot translate, such as function-pointer dispatch, is modelled by hand in Lean definitions, never axioms. The model's file quotes the Rust it models, and `admin/prove` fails when the quote no longer matches the source.
- `Axioms.lean` pins, with `#guard_msgs`, the axioms each top-level theorem rests on, so growing the trust base fails the build.
- Trusted: each restatement, each hand model, the translation and Aeneas's models of `core`, and the transliteration, as for the other s2n-bignum entries.
