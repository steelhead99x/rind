# [L] x86_64's AES-GCM for every IV, tag, and key size, and the AVX-512 by-16, are proven

## Goal

rind's remaining x86_64 AES-GCM paths are proven: `aead::gcm::Key`'s IVs other than 96 bits and its truncated tags, which run `encrypt_any` and `decrypt_any` on the by-8 kernels, AES-192 keys, which run by-8 on every tier, and the optional AVX-512 by-16 AES-CTR and GHASH, so every input rind takes on AES-NI CPUs reaches a proof.

## Plan

- Done ([moq-dev/rind#633](https://github.com/moq-dev/rind/pull/633)): the by-8 AES-CTR and GHASH, the PCLMULQDQ table, the counter, J0 for 96-bit IVs, the length block, the tag, and the AEAD API's `seal` and `open` on the SSE tier (AES-NI and PCLMULQDQ without AVX) and at every length rind takes on Vale's tier (`proofs/Rind/X86_64/{GhashClmul,AesGcmBy8,AesGcmClmul,AesGcmAead}.lean`), against `Rind/Vale.lean`'s `gcm_encrypt_LE` and `gcm_decrypt_LE` without their 2^32 bound. It landed as a self-contained step, with this quest rewritten to the rest (maintainer, 2026-11-12: ✅ merge it so; rejected: keep extending that PR).
- Other IVs and truncated tags: this quest owns them (maintainer, 2026-11-09: ✅ here; rejected: in m3's Vale-tier quest, which kept only the 12-byte, full-tag glue). Add `mid::aes_gcm::AesGcm::{encrypt_any, decrypt_any}` as `admin/prove` start points. Prove `aes_gcm::initial_counter` is `compute_iv_BE`'s GHASH branch over `ClmulTable::add` and the IV's length block, as `add_lengths_spec` does for the AAD's, and `ct_equal` on the tag's prefix against Vale's tag truncated. Then make `GcmKey.lean`'s `seal_other_iv` and `open_other` arms concrete, and prove the `gcm_key_*` theorems for any IV and `TagLength`.
- AES-192: [the AES header-protection quest](/quest/m4/verified/aes-header-protection.md) proves `aes192_expand` and `aes_block` against FIPS 197's 6-word key expansion, which it adds to `Rind/Vale.lean`'s `Algorithm`. This quest then drops `HwKeyIs`'s `Aes192 => False`, extends `AesGcmBy8.lean`'s `encrypt_eq` to the 12-round schedule, and so covers AES-192 in every AES-GCM theorem.
- AVX-512 by-16: model `_cipher_avx512`, `Counter512`, and `GhashTableAvx512::add` with the 512-bit intrinsics, extending `Rind/X86_64/Simd.lean`, against the same specs. It runs from 256 bytes to 2 KB on the AVX-512 tier, which [the VAES quest](/quest/m4/verified/aes-gcm-x86-vaes.md) composes with BoringSSL's kernels; short messages there run by-8, which `by8_spec` covers for any `ClmulTable`, once `cipher`'s dispatch on those tiers is proven.
- Refusals: the theorems take AAD under 2^61 bytes and messages up to 2^36 - 32. Stating that `check_gcm_lengths` refuses longer ones with `WrongLength`, leaving the buffer as it was, would make them total.
