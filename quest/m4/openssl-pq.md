# [M] Expose ML-KEM and ML-DSA in rind-openssl for OpenSSL 3.5+

## Goal

`rind-openssl` registers `rind`'s ML-KEM (512, 768, 1024) and ML-DSA (44, 65, 87) implementations as OpenSSL 3.5+ provider algorithms (`OSSL_OP_KEYMGMT`, `OSSL_OP_KEM`, `OSSL_OP_SIGNATURE`, plus encoder/decoder support), interoperable with OpenSSL's `default` provider in TLS 1.3 hybrid key exchange and `openssl pkeyutl` / `EVP_PKEY` tests.

## Plan

Planned with the maintainer on 2026-11-21 (`/quest-plan`): ✅ add ML-KEM and ML-DSA support to `rind-openssl` (rejected: skip). Placed in `m4` alongside the OpenSSL provider work.

- Wire ML-KEM-512, ML-KEM-768, and ML-KEM-1024 into `rind-openssl` (`OSSL_OP_KEYMGMT` + `OSSL_OP_KEM` dispatch tables, keygen, encapsulate, decapsulate, raw/PKCS#8/SPKI key import/export, and `EVP_PKEY` parameter queries matching OpenSSL 3.5's provider contract).
- Wire ML-DSA-44, ML-DSA-65, and ML-DSA-87 into `rind-openssl` (`OSSL_OP_KEYMGMT` + `OSSL_OP_SIGNATURE` dispatch tables, pure and context-string signing/verifying, raw/PKCS#8/SPKI import/export).
- Add cross-provider interoperability tests verifying keys, ciphertexts, and signatures generated by `rind-openssl` verify/decapsulate under OpenSSL 3.5's built-in `default` provider and vice versa (including TLS 1.3 `X25519MLKEM768` handshake with `openssl s_server`/`s_client` if OpenSSL 3.5 is available in Nix/CI).
- Update `rind-openssl/README.md` with the newly supported post-quantum algorithms and minimum OpenSSL version requirement (3.5+).
