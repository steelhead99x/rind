# [XL] armv7's Curve25519 is proven

## Goal

X25519 and Ed25519 earn the ✓ on armv7.

## Plan

- Runs: curve25519-dalek's serial 32-bit backend for X25519 key generation's base multiplication and all of Ed25519 (`mid::portable::ed25519` and `edwards25519`), under rind's canonical-y and small-order checks; with NEON, BoringSSL's `neon2` X25519 assembly (from SUPERCOP) for the shared secret. HACL*'s X25519 was 1.9x slower than `neon2` and its Ed25519 3.5x slower to sign, so switching fails the speed rule.
- Already proven: X25519 on a CPU without NEON, from the agreement API's `PrivateKey` down to dalek's `MontgomeryPoint::mul_clamped` and `mul_base_clamped`, whose Beneficial AI Foundation (BAIF) theorems `proofs/Rind/Armv7/Dalek.lean` restates as axioms; `admin/prove dalek` checks that the crates.io release rind builds translates to the code BAIF's proofs are about (`proofs/README.md`, "curve25519-dalek's proofs"). Both armv7 bench tiers have NEON, so armv7's `x25519-ecdh` earns its ✓ only with `neon2` proven.
- X25519 with NEON: prove `neon2`'s `x25519_NEON` in HOL Light on the AArch32 model's NEON in `thirdparty/s2n-bignum/aarch32/`, check its bytes with `admin/prove bytes`, and restate the theorem in `proofs/Rind/Armv7/Curve25519.lean` as `ladder_neon`'s contract. `DalekCpu` then drops `o = none` and `cpuX25519 (some _)` becomes that theorem's spec, as x86_64's IFMA case does, so every theorem, the public key's included, holds on every CPU. Then add armv7's `x25519-ecdh` to `benchmarks/verified.toml`.
- Ed25519: extend armv7's translation to the signature API's Ed25519 and `mid::portable::{ed25519,edwards25519}`, restate BAIF's theorems about each dalek function they call (`CompressedEdwardsY::decompress`, `EdwardsPoint::mul_base`, the double-base multiplication, `Scalar::from_canonical_bytes`, `from_bytes_mod_order_wide`, `clamp_integer`) in `Rind/Armv7/Dalek.lean`, add each to `admin/prove`'s `dalek_roots` so the identity check covers it, and to `dalek_copied` any function a translation patch on its path copies into its caller, and prove the glue against `Rind/Ed25519.lean`'s spec, bridging BAIF's Edwards specs to it as `Rind/Dalek.lean` bridges its X25519. Its SHA-512 runs armv7's assembly, which [armv7's assembly](/quest/m5/verified-armv7/assembly.md) proves; until then Ed25519's theorems take SHA-512's contract as a hypothesis.
