# [XL] armv7's Curve25519 is proven

## Goal

X25519 and Ed25519 earn the ✓ on armv7.

## Plan

- Runs: curve25519-dalek's serial 32-bit backend for X25519 key generation's base multiplication and all of Ed25519 (`mid::portable::ed25519` and `edwards25519`), under rind's canonical-y and small-order checks; with NEON, BoringSSL's `neon2` X25519 assembly (from SUPERCOP) for the shared secret. HACL*'s X25519 was 1.9x slower than `neon2` and its Ed25519 3.5x slower to sign, so switching fails the speed rule.
- Already proven: X25519 on a CPU without NEON, from the agreement API's `PrivateKey` down to dalek's `MontgomeryPoint::mul_clamped` and `mul_base_clamped`, and Ed25519 on CPUs with NEON, from the signature API's `ed25519::KeyPair` and `ed25519::PublicKey` down to the dalek functions `mid::portable::ed25519` calls, in `proofs/Rind/Armv7/Ed25519.lean`. `proofs/Rind/Armv7/Dalek.lean` restates Beneficial AI Foundation's (BAIF's) theorems about each as axioms, and `admin/prove dalek` checks that the crates.io release rind builds translates to the code BAIF's proofs are about (`proofs/README.md`, "curve25519-dalek's proofs"). Both armv7 bench tiers have NEON, so armv7's `x25519-ecdh` earns its ✓ only with `neon2` proven.
- X25519 with NEON: prove `neon2`'s `x25519_NEON` in HOL Light on the AArch32 model's NEON in `thirdparty/s2n-bignum/aarch32/`, check its bytes with `admin/prove bytes`, and restate the theorem in `proofs/Rind/Armv7/Curve25519.lean` as `ladder_neon`'s contract. `DalekCpu` then drops `o = none` and `cpuX25519 (some _)` becomes that theorem's spec, as x86_64's IFMA case does, so every theorem, the public key's included, holds on every CPU. Then add armv7's `x25519-ecdh` to `benchmarks/verified.toml`.
- Ed25519's ✓: its theorems take `RunsSha512`, which takes NEON, since `proofs/Rind/Armv7/Sha512Entry.lean` restates the HOL Light proof of aws-lc's NEON `sha512-armv4` routine and the integer one, which a CPU without NEON runs, has none yet. Once [armv7's assembly](/quest/m5/verified-armv7/assembly.md) proves it, restate it there about `compress_nohw`, so `RunsSha512` keeps only the entry checks, and add armv7's Ed25519 rows to `benchmarks/verified.toml`.
- `Rind/Armv7/Ed25519.lean` repeats x86_64's byte lemmas and high-level theorems, since its key types hold dalek's points where x86_64's hold s2n-bignum's limbs. Writing the common part from one file, as `admin/prove` writes armv7's SHA-512 context proof from x86_64's, would prove a change to the Ed25519 API once.
