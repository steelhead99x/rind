# [M] cipher::ChaCha20 earns the ✓ from pyca/verified-garbage's proof

## Goal

Every VG routine `cipher::ChaCha20` runs is imported as a theorem, so it earns the ✓ on the tiers and lengths that run it: on x86_64, `vg_chacha20_init` with `vg_chacha20_apply_avx2` and `vg_chacha20_apply_avx512vl` from 256 bytes ([kixel-ai/rind#811](https://github.com/kixel-ai/rind/pull/811)), and on aarch64 `vg_chacha20_init` with `vg_chacha20_apply_sve2` from 128 bytes and `vg_chacha20_apply_neon` from 192 to 256 bytes and from 448 ([kixel-ai/rind#882](https://github.com/kixel-ai/rind/pull/882)).

## Plan

- x86_64's import and glue landed in [kixel-ai/rind#853](https://github.com/kixel-ai/rind/pull/853): `Rind/X86_64/VgChaCha20.lean` restates `Stream.init_verified` and `Stream.apply_verified` for AVX2 and AVX-512 VL as one axiom per wrapper, and proves `chacha20_apply_keystream` from them over the split and the counter the kernel's tail resumes from, with the kernel's contract as the hypothesis `Kernel`, which [kixel-ai/rind#869](https://github.com/kixel-ai/rind/pull/869) proves for [the x86_64 cipher quest](/quest/m4/verified/chacha20-poly1305-x86/cipher.md). `admin/import-vg` pins VG's `0aa40d6c` ([kixel-ai/rind#855](https://github.com/kixel-ai/rind/pull/855), [kixel-ai/rind#877](https://github.com/kixel-ai/rind/pull/877)), which has both architectures' stack-slot fixes ([pyca/verified-garbage#5378](https://github.com/pyca/verified-garbage/pull/5378) and [#5391](https://github.com/pyca/verified-garbage/pull/5391)), so x86_64's VG ChaCha20 holds the ✓.
- aarch64: import those routines the same way, under [the m4 epic's composition rule](/quest/m4/verified/README.md#composition-rule), as [the epic](/quest/m2/verified-garbage/README.md)'s Plan settles, and prove rind's glue around them (`low/aarch64/chacha20.rs`'s `cipher` and `cipher_vg`), with rind's NEON code's contract as a hypothesis, as x86_64's takes its kernel's. Unlike x86_64, VG runs whole requests there, so no tail resumes on rind's code.
- `benchmarks/verified.toml` takes no entry: bare ChaCha20 is not a report row, and the report's ChaCha20-Poly1305 rows run aws-lc's one-pass routines, not these.
- Model gaps, which the maintainer ruled on 2026-11-17 ([kixel-ai/rind#815](https://github.com/kixel-ai/rind/pull/815#issuecomment-6943056592)) as [the epic](/quest/m2/verified-garbage/README.md)'s Plan records: ✅ the stack-slot gap is reported upstream and this ✓ waits for VG's fix and a re-pin (rejected: a rind-side check that each stack load reads only bytes its own frame stored; accepting the model as is), which the `0aa40d6c` pin has met. ✅ The `NoResidue` undefined-flags gap is reported upstream and does not hold this ✓, since rind imports no `NoResidue` theorem (rejected: not reporting it).
