# Speed regressions fail the weekly bench by its second run after they land

## Goal

The weekly bench fails on any gap nobody decided, on every tier and at every size people run: it ranks every benchmark it times, and it times the tiers and AEAD sizes no host or row covers today.

## Plan

Decided with the maintainer on 2026-11-09, after an audit of the whole tree: ✅ plan speed measurement and portable speed (rejected: correctness tooling only, or measurement without portable speed work). Measurement joins m2 with the other tooling; the cold tiers' speed work was m3's, and has landed.

The audit found rind level or ahead in every ranked cell on mainline x86_64, aarch64, and armv7 with the crypto extension. What it could not vouch for is what nothing measures: the weekly run prints a summary and never fails, about a third of its benchmark IDs are unranked, and no host or forced tier times aarch64 with the crypto extension but without SHA-3, which is Graviton 2, the Raspberry Pi 5, and most phones.

All three have landed since: the weekly bench fails on a gap nobody decided once the run before it showed the same gap, so one noisy run does not fail it and a real gap fails on its second ([kixel-ai/rind#560](https://github.com/kixel-ai/rind/pull/560); `admin/bench-report gate --previous`, `.github/workflows/bench.yml:363`), it has rows for the tiers nothing timed ([kixel-ai/rind#556](https://github.com/kixel-ai/rind/pull/556)) and for the AEADs at 128, 256, and 512 B ([kixel-ai/rind#559](https://github.com/kixel-ai/rind/pull/559)), and `admin/bench-report` refuses a benchmark ID no decision lists.

The benchmark report refresh, which each minor release's quest creates, keeps the report on the dedicated hosts. This epic makes the weekly bench catch what lands between refreshes.

Decided 2026-11-12 (maintainer, /quest-audit), after an audit of what the benchmarks still cannot see:

- Hosts: `fedora` joins the report as its AVX-512 host ✅ (rejected: ad hoc runs only; leave the host list alone). This reopens the 2026-11-03 host list: no report host had AVX-512, so no host table showed the AVX-512 AES-GCM kernel, the IFMA RSA routines, or ML-KEM's 8-way sampler against every library. The CPU tier table does time them weekly, on GitHub's EPYC runners against aws-lc-rs and ring, which the interview missed; told so, the maintainer confirmed the quest the same day. `fedora` joined in [kixel-ai/rind#949](https://github.com/kixel-ai/rind/pull/949), and a second refresh before 0.4 ([kixel-ai/rind#991](https://github.com/kixel-ai/rind/pull/991)) reran every host but `desktop`, which never had a quiet window. `nixos2` is dead and left the report in the 0.4 refresh, [kixel-ai/rind#619](https://github.com/kixel-ai/rind/pull/619).
- Shared hosts: decided 2026-11-27 (maintainer, in [kixel-ai/rind#1103](https://github.com/kixel-ai/rind/pull/1103)) ✅ `collect` times `nixos`, `desktop`, and `fedora`, which CI runners and agent sessions keep at about twice their CPU count, on the host's last two whole cores (a hybrid CPU's last two performance cores), keeping every other top-level cgroup slice off only those for the timing, so the other work keeps every other core and mbx sizes its pool from them; those hosts time no every-logical-CPU rows and no build cost (rejected: holding the whole host, which starved its other work, as #1103 first tried; dedicated hosts only; load-annotated rows, as [kixel-ai/rind#938](https://github.com/kixel-ai/rind/pull/938) proposes). On `nixos`, with 6 to 13 other CPUs busy, the same code and harness on reserved cores put 2.5% of rind's ratios to other libraries more than 10% from its quiet run's, against 1.1% between two quiet runs, the same p5 to p95 spread (0.95 to 1.05), and reserved reruns repeat within about 1%. A loaded neighbour still shares the L3 cache and the power budget: `fedora`, with 28 of 32 CPUs busy, slowed every library by 8 to 19%, unevenly. The reservation needs systemd and passwordless sudo, sets the slices' whole CPU range back explicitly, since systemd 262 ignores an empty `AllowedCPUs=`, and leaves a timer that releases it if the run dies.
- Rows: HPKE, the VRF, and blind RSA, which landed without one, and rind-rustls handshakes across threads, get rows.
- Left out: binary size per target, which `admin/build-cost` already reports in BENCHMARKS.md, and a wasm row, which no consumer has asked for.
