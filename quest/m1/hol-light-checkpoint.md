# [S] HOL Light sessions start from a checkpoint

## Goal

A repo helper starts an interactive HOL Light session with s2n-bignum's `base.ml` for an architecture already loaded, restored in seconds from a checkpointed image built once per architecture and set of inputs, so agents developing proofs stop reloading the model and stop building REPL servers of their own. `admin/prove` keeps compiling the proofs natively.

## Plan

Decided with the maintainer on 2026-11-12, from read-only audits of the maintainer's agent hosts: ✅ a checkpointed session image after `base.ml` loads, once per architecture, shipped as a repo helper.

- The cost: each session reloads `base.ml`, which agents estimate at 2 to 20 minutes, single-threaded and peaking at 19.6 GB. Gated sessions took 4.3 CPU-h in 1.8 days, and agents built REPL servers (`holserver.sh`, `send.sh`) that run outside `quest gate`.
- Checkpoint with DMTCP or CRIU, both in nixpkgs, as HOL Light's README describes. DMTCP is recommended: it runs unprivileged, and HOL Light's `make-checkpoint.sh` already loads a statement such as `needs "x86/proofs/base.ml"` before checkpointing, while CRIU needs privileges and selfie, HOL Light's third option, is not packaged. That script catches an exception from the statement and still marks the session loaded, and by default HOL Light's `use_file` prints an error in a nested file and returns, so the helper sets `use_file_raise_failure := true` before `needs`, writes its marker only if `needs` then returns with no handler catching its exception, and publishes an image only after that marker, failing otherwise.
- The session sees what `admin/prove hol-light` checks: the same load path, with `proofs/hol-light/s2n-bignum/` and the patched x86 model ahead of the submodule. Key each image by HOL Light's store path, the submodule's commit, and those carried files, refusing to build or restore one while the submodule has uncommitted changes, since its commit then no longer names the files `admin/prove` reads, keep it outside the worktree so worktrees on the same inputs share it, and build it under `quest gate`. `admin/prove` puts absolute worktree paths on `HOLLIGHT_LOAD_PATH`, its patched model among them under the worktree's build output, and a restored session keeps the `load_path` it was checkpointed with, so build the image from copies of the carried files and the patched model kept beside it, outside any worktree, and on restore rebind `load_path` to the current worktree's directories, in `admin/prove`'s order, with the image's copy of the patched model in place of the build output's. Verify by restoring in two worktrees, each loading a proof file only it has, then removing the first and restoring in the second again.
- Start the restored session in a directory of the current worktree prepared as `admin/prove` prepares `.tmp/prove/hol-light`, with the objects rind's proofs read relative to it, such as `x86_64/bn_mul_mont_nohw.o`, so an existing proof runs there. Let an agent run a file in a restored session and read the output without a server, if restore is fast enough; record the image's size and restore time.
- Name the helper in `proofs/README.md`'s HOL Light section, where agents writing proofs look.
